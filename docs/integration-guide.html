Overview

The Api service exposes a REST surface under /meetings/... and a SignalR hub at /hubs/meeting for live status. A meeting moves through recording, upload, background transcription/diarization, and lands in Ready — the frontend's job is to create it, upload audio to a signed URL, then either poll or subscribe for the status change.

Flow in short: create meeting → request an upload URL → PUT the audio file directly to storage → mark the recording complete → wait for Ready via SignalR → fetch the transcript.

Authentication

Every REST call and the hub connection require a Firebase ID token as a bearer token. Sign the user in with the Firebase JS SDK, then attach getIdToken() to each request — it self-refreshes, so don't cache it beyond a request.

lib/api.ts
import { getAuth } from "firebase/auth";

const BASE_URL = import.meta.env.VITE_API_BASE_URL;

async function authHeader() {
  const user = getAuth().currentUser;
  if (!user) throw new Error("Not signed in");
  const token = await user.getIdToken();
  return { Authorization: `Bearer ${token}` };
}

export async function api<T>(path: string, init: RequestInit = {}): Promise<T> {
  const res = await fetch(`${BASE_URL}${path}`, {
    ...init,
    headers: { "Content-Type": "application/json", ...(await authHeader()), ...init.headers },
  });
  if (!res.ok) throw new Error(`${res.status} ${res.statusText}`);
  return res.status === 204 ? (undefined as T) : res.json();
}

Read & status

GET/meetings/{meetingId}
Full MeetingDto — id, title, status, failure reason, participant hints.
GET/meetings/{meetingId}/status
Lightweight poll target — just id, status, failureReason, failureMessage. Prefer the SignalR event below over polling this.
POST/meetings/{meetingId}/retry?recordingId=...
Re-queues processing for a Failed meeting against a given recording. Returns 202.
Status values: Recording → Uploaded → Processing → Ready, or Failed with a failureReason of TranscriptionFailed, DiarizationFailed, StorageError, or MergeFailed.

Recordings

async function uploadRecording(meetingId: string, file: File) {
  const { recordingId, uploadUrl } = await api<GetUploadUrlResponse>(
    `/meetings/${meetingId}/recordings/upload-url`,
    { method: "POST", body: JSON.stringify({ contentType: file.type, fileExtension: "webm" }) },
  );

  // direct PUT to storage — no auth header, the URL itself is the credential
  await fetch(uploadUrl, { method: "PUT", headers: { "Content-Type": file.type }, body: file });

  await api(`/meetings/${meetingId}/recordings/${recordingId}/complete`, {
    method: "POST",
    body: JSON.stringify({ durationMs: file.size }), // use actual recorded duration
  });
}

download an export
async function downloadTranscript(meetingId: string, format: "Srt" | "Vtt" | "Docx" | "Txt") {
  const res = await fetch(`${BASE_URL}/meetings/${meetingId}/export?format=${format}`, {
    headers: await authHeader(),
  });
  const blob = await res.blob();
  const url = URL.createObjectURL(blob);
  const a = document.createElement("a");
  a.href = url; a.download = `transcript.${format.toLowerCase()}`; a.click();
  URL.revokeObjectURL(url);
}

Speakers

PATCH/meetings/{meetingId}/speakers/{speakerId}
Renames a diarized speaker label. Body: { label }. Returns the updated SpeakerDto — use this to let users relabel "Speaker 1" as a real name after reviewing the transcript.

Realtime updates

The hub at /hubs/meeting requires the same bearer token. Join a meeting's group after connecting, then listen for two events pushed as transcription/diarization work completes in the background.

EventPayload
meetingStatusChanged{ meetingId, status }
transcriptSegmentReadyTranscriptSegment
hooks/useMeetingHub.ts
import * as signalR from "@microsoft/signalr";

export async function connectMeetingHub(meetingId: string) {
  const token = await getAuth().currentUser?.getIdToken();

  const connection = new signalR.HubConnectionBuilder()
    .withUrl(`${BASE_URL}/hubs/meeting`, { accessTokenFactory: () => token! })
    .withAutomaticReconnect()
    .build();

  connection.on("meetingStatusChanged", (e: { meetingId: string; status: string }) => {
    // update local state when e.status becomes "Ready" or "Failed"
  });

  connection.on("transcriptSegmentReady", (segment: TranscriptSegmentDto) => {
    // append to the live transcript view
  });

  await connection.start();
  await connection.invoke("JoinMeetingGroup", meetingId);
  return connection; // call connection.invoke("LeaveMeetingGroup", meetingId) + connection.stop() on cleanup
}

Errors

Failures come back as RFC 7807 problem details: { status, title }. The JWT middleware returns a bare 401 with no body when the token is missing or invalid.

400 — validation failed, title lists the errors
401 — missing or expired token
403 — authenticated, but not this meeting's owner
404 — meeting, recording, or speaker not found

Full example: a meeting-detail hook

Combines the REST read with the live subscription — a typical shape for a meeting detail screen.

hooks/useMeeting.ts
export function useMeeting(meetingId: string) {
  const [meeting, setMeeting] = useState<MeetingDto | null>(null);
  const [transcript, setTranscript] = useState<TranscriptSegmentDto[]>([]);

  useEffect(() => {
    let connection: signalR.HubConnection | undefined;

    (async () => {
      setMeeting(await api<MeetingDto>(`/meetings/${meetingId}`));
      connection = await connectMeetingHub(meetingId);

      connection.on("meetingStatusChanged", async () => {
        setMeeting(await api<MeetingDto>(`/meetings/${meetingId}`));
      });
      connection.on("transcriptSegmentReady", (segment: TranscriptSegmentDto) => {
        setTranscript((prev) => [...prev, segment]);
      });
    })();

    return () => { connection?.invoke("LeaveMeetingGroup", meetingId); connection?.stop(); };
  }, [meetingId]);

  return { meeting, transcript };
}
